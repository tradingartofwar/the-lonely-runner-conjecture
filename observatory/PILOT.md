# The first 24 hours

The private board is the record of which question has actually been claimed. The first measurement window begins when the coordinator seeds the hosted queue. Pause on the board stops new leases. Existing leases can finish and record results. A cloud task checks the queue every four hours and drains eligible work immediately. Six research wakes are followed by a dedicated first-day measurement wake. The hosted service fences grants at the deadline even if an earlier wake is still active.

## Unattended coordinator

Use only the user's existing Codex/Work plan. If the plan cannot execute the work, leave the job queued, report the hold on the board and stop. Never select an API key, purchase credits or change billing. A wake needs the Sites connection, the research repository and Python 3.10+. A scheduled worker runs outside the setup chat. The board is a viewer and operator control, and can remain closed.

Research produces a fingerprint of the full output and the verifier recomputes every physical clearance and aggregate before promoting a finding. Follow the coordinator's returned next job immediately in the same wake. Do not simply repost old results or run the initial bootstrap again.
3. If a queued job has no deterministic protocol, read its question, immutable source and associated finding.
