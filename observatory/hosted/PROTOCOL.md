# Hosted Observatory pilot

A signed-in owner can open the board or pause new claims. An unattended worker uses the Site's owner-private service access. Obtain the existing Site's access through its supported Sites connection each run. Send the service bearer only to that Site, in the `OAI-Sites-Authorization` header. Sites consumes the credential before the Worker runs. Keep the Site owner-private. The service endpoint accepts requests without a browser origin or visitor identity. Credentials, leases and raw logs stay out of the board and published artifacts.

## Package the existing Site

Keep the previous static export's seven files at checkout-root `archive/` (including its `demo/` directory). Copy this source directory to checkout-root `hosted/`. Keep the original project ID in `.openai/hosting.json`, remove `static`, set `d1` to `"DB"` and set an unused `r2` to `null`. From the Site checkout run:

```sh
node hosted/build.mjs
node --test hosted/test-worker.mjs
```

The dependency-free build emits `dist/server/index.js`, `dist/.openai/hosting.json` and the Drizzle migration. It promotes the tracked migration to checkout-root `drizzle/` for the Sites packager. It refuses conflicting migration history. Preserve the complete Drizzle directory when publishing. Sites provisions D1 and applies pending schema changes. No API handler creates tables. The Worker embeds all required assets. The archived board lives at `/archive/`, with the prior trajectory demo also at `/demo/`.

The default test uses Node 22.13+ built-in SQLite. For a native integration run, set `OBSERVATORY_MINIFLARE` to an installed Miniflare package directory and `OBSERVATORY_WORKER_BUNDLE` to the absolute path of the built Worker. This runs the HTTP tests in workerd using a real local D1 binding. Tests use an isolated, temporary database. The live production proof is a separate claim, return and readback through the deployed private service.

## Service dispatch

`GET /api/pilot` returns a current projection and omits lease secrets. `POST /api/dispatch` requires JSON with `action` and a unique `request_id`. Reuse that ID for a network retry of the exact same payload. Use a new ID for a new attempt or poll. A stale claim replay returns HTTP 409. A repeated successful completion returns the original receipt. All state transitions, counter changes, evidence links and idempotency receipts commit in one conditional D1 write. HTTP 503 can be retried with the same ID.

| Action | Payload and effect |
| --- | --- |
| `begin` | Starts the original 24-hour measurement on first use. Later calls always return the original dates and never change active bounds, counters or pause. |
| `advance` | Day-end coordinator only. Send `expected_ends_at` exactly as read from `pilot.ends_at`. A matching elapsed deadline, clear owner pause and provider hold, no unexpired job lease, and a queued question linked to a hosted verified finding (or that question’s pending independent audit) are required. The response has `advanced`, `reason`, `window_number`, `started_at`, `ends_at`, and, on success, `qualifying_job_id`. An idle closeout returns `reason:"no_verified_followup"` and `decision_id` and opens no new window. |
| `seed` | `id`, `role` (researcher or challenger), `task`, optional verified `source_finding_id`. A reproducible bounded job may also supply `protocol` (cohorts or wrap) and a post-commit `seed` of 32 lowercase hexadecimal digits. |
| `claim` | `worker`, `run_id`, `mode` (model or deterministic), optional `id` or `role`. Optional `controller_run_id` links the claim to an admitted coordinator observation, retained on the job and each claim event. Response contains `job`, `lease_token`, `handoff.parent` and `handoff.finding`. When blocked, it contains `job:null` and `reason`. Supply a real distinct executor identity and actual run ID. The Worker never runs a model. |
| `heartbeat` | `id`, `worker`, `lease_token`. Renew during long work, before the 20-minute lease expires. A rejected heartbeat or completion fences out that attempt. |
| `release` | Same lease identity and `reason`. Return an interrupted assignment for retry. A third unsuccessful attempt opens an owner decision. |
| `complete` | Same lease identity and `summary`, repo-relative `artifact`, exact `replay` command and `revision` (Git revision or SHA-256). A research or challenger return enters `submitted` and atomically queues an independent verifier. Optional `audit_question` supplies a specific check. Optional `result_digest` stores the 64 lowercase hex digits of the returned result’s SHA-256. The verifier receives it in `handoff.parent.result_digest`. A verified verdict must reproduce the same digest when the proposal supplies one. |
| Verifier `complete` | Also send `verdict` (verified, refuted or inconclusive) and a meaningful `next_question` or `decision`. The successful receipt identifies any new `finding_id`, `next_job_id` and `decision_id`. A verified finding and its proposed next job are committed together. Optional `next_protocol` and `next_seed` fix the reproducible continuation. Each verifier and subsequent researcher must be acquired by a separate executor context from the return it is checking or following. |
| `observe` | A real running coordinator reports `run_id`, `worker`, `mode`, `state` (running, completed or failed) and `task`. The service records its own current timestamp. This observability action grants no lease. The first observation of an actual model coordinator run charges one reservation. A terminal observation and a retry with the same request ID do not charge again. At the shared limit a new, already-awake controller is recorded separately and receives HTTP 429; it must stop before research. These wakes appear in `evaluation.over_budget_controller_runs` and remain eligible for real usage receipts. |
| `record` | `source` plus up to 60 actual historical `events` (`time`, `role`, `state`, `task`, optional worker, job ID, evidence path, command and revision). Optionally attach an independently reviewed `finding` with `id`, `verified_at`, `verifier` and all four evidence fields from `complete`. Original timestamps and import provenance remain distinct from hosted job claims. To attribute an actual model session, record both its actual `run_id` and `mode:"model"`. |
| `telemetry` | `source`, `measured_at`, optional `windows` of `label`, `remaining_percent`, `resets_at`; or `plan_error` from a failed read. The latest failed read preserves the last successful allowance snapshot. An observed `limit_reached:true` or `auth_unavailable:true` stops model leases. A subsequent successful account read can clear a quota hold. A runner authentication hold requires a positive service-side `plan_available:true` after the runner regains access. Operator pause is independent. |
| Run `telemetry` | Attach the actual Observatory `run_id`, input and output counts and optional cached-input count. Submit cumulative counts for that run's Pacific day. Cached input is a subset of input. A later genuine receipt can fill unknown counts. Supply `day` (YYYY-MM-DD) for measured day-specific slices of a run crossing Pacific midnight. Unsplit cross-day data has no daily allocation. Unrecognized run IDs are rejected. |
| `decision` | `text` records a decision that needs Vance. |

Capture the return artifact or reproducible immutable revision before completing. An independent verifier must run its own check and record any falsification. A verifier can close a question with a decision when further automatic work has no justified assignment. Read the response's next job ID immediately and hand it to an independently executing worker. There is no time spacing between related jobs. If scheduling or authorization is unavailable, leave the job queued and record that state. A queued assignment is visible separately from a real claim.

Each 24-hour window has its own deadline and budgets. Normal claims stop at expiry. At day-end the service retains a frozen snapshot in `windows[]` with original start, deadline, closeout capture time, research evaluation and observed model usage. Events, returns, decisions and meter receipts remain in the same ledger. The coordinator invocation that performs closeout is charged to its original window even if it reports completion later. An eligible continuation starts at the real advance time. The board exposes the new `pilot.window_number`, each prior snapshot, and separate Pacific calendar-day usage. Replaying a request or an earlier window deadline cannot reopen one. Use a new request ID after a real blocker clears. The two active leases apply to each window. Model coordinator invocations and model job grants (including retries) share 18 reservations. At most 11 model job attempts are granted, preserving space for the six scheduled work wakes and one closeout. Each new model invocation needs its own run ID and reservation. When one real invocation is both controller and worker, report the same ID to both endpoints. Reusing a model job run ID for another job or retry is rejected. The board shows reservations used and remaining. The Sites scheduler starts a controller externally before it can report; a wake observed over cap must immediately stop and remains visible separately. Deterministic jobs are counted separately. Leases already authorized can return while paused. No paid API, additional credits or hosting credential is requested by this Worker. Service callers must select the existing plan and report actual account limitations. Token and allowance data are distinct. Missing observations remain unknown. Daily model and exact-computation run counts deduplicate actual run IDs. Today's measured token totals cover identified Observatory model sessions with matching receipts, summing input and output once. The hosted follow-up pickup count includes children enqueued by a hosted verifier that a subsequent researcher actually claimed.

Browser-only `POST /api/operator` requires the same-origin Origin header, a Sites-authenticated visitor identity and JSON. The owner can send `{"action":"pause"}` or `{"action":"resume"}`. The optional owner-local Codex meter can send `action:"usage"`, `measured_at`, `request_id`, and either one or two plan windows or `plan_error`. This narrow route accepts no token totals, worker controls or service credentials.
