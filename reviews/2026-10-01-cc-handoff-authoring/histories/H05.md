# Cedar shared-resource planning

This is a synthetic planning problem. All quantities are exact abstract units, not estimates for a real facility. The cutoff is the end of Day 12. The incoming planner must choose a feasible simultaneous pair, explain why earlier proposals changed, and reconsider the choice if a requirement or resource allowance changes. Three jobs are available: A, B, and C. Jobs are indivisible and run for the same full session. Their resource requirements add when run together. A job cannot borrow spare resources from a later session or split its work across time unless the question explicitly changes that rule.

## D01 — Day 1, goal

The initial goal is to run exactly two distinct jobs simultaneously and maximize their total output. There are three shared resource types: staff, memory, and power. A pair is feasible only if its summed requirements fit all three current caps at the same time. Feasibility is a supplied deterministic definition, not a probability estimate. Individual jobs can each be feasible while a proposed pair is not. The planner should retain enough of the alternatives to respond if a later request requires a particular job instead of simply maximizing the original objective.

## D02 — Day 2, job A

Job A needs four staff units, six memory units, and four power units for the session. It produces eight output units. Its setup is already complete and adds no further resource cost in this scenario. The team likes A because its output is easy to demonstrate, but preference does not change either its resource needs or the objective. These quantities remain fixed through the cutoff. A screen showing A alone reports it feasible under the provisional caps; that statement concerns the single job, not any pair containing it.

## D03 — Day 3, job B

Job B needs five staff units, five memory units, and five power units. It produces ten output units. The prototype schedule gives B the largest output label among the three jobs. It also lists a separate staff-only check to help the coordinator reserve people. That check is deliberately incomplete as a feasibility decision because memory and power are also shared. All three resource values apply simultaneously for the entire session. There is no option in the supplied catalogue to lower B's resource needs by accepting a smaller output.

## D04 — Day 4, job C

Job C needs three staff units, four memory units, and three power units and produces six output units. Its preparation note describes it as a possible companion for either A or B, depending on the caps. That wording is conditional rather than an approval of both pairs under every future budget. C is a distinct job and cannot be run twice to satisfy the two-job requirement. The project has no other job candidates. The incoming planner may therefore enumerate all three possible unordered pairs without assuming an unexplored external alternative exists.

## D05 — Day 5, provisional caps

The provisional shared caps are eight staff units, ten memory units, and eight power units. Each job fits by itself. An early slide highlights A and B because their separate outputs sum to eighteen, the largest unconstrained pair total. The slide was produced before the pair-resource calculation and is marked proposed. The pair's total requirements must be computed from both jobs. Neither an individual green badge nor the unconstrained output ranking establishes that this pair can run within the shared caps.

## D06 — Day 6, pair discussion

The team calculates candidate pairs and keeps the job-level requirements rather than only saving the winning name. A proposed rental would raise the staff cap, but it would not change memory or power. The rental quote is for staff capacity only. The coordinator explicitly rejects reading the phrase more capacity as an increase to every resource. The quote remains a proposal. No rental has been accepted, and the current staff cap is still eight. The project does not permit staff to substitute for missing memory or power units.

## D07 — Day 7, resource correction

The facility corrects the memory allowance from ten to nine units for the planned session. This is an adopted change and supersedes the earlier memory cap. The staff cap stays eight and the power cap stays eight. The correction changes the feasibility of some combinations without changing their output or job-level requirements. Old pair calculations under the ten-unit allowance are preserved with their date. They are useful for a future changed-budget question but cannot be silently reused as current approvals.

## D08 — Day 8, staff-only rental

The rental proposal is made concrete: it would raise the staff cap from eight to ten units, leaving the memory cap at nine and the power cap at eight. Its availability is assumed if a later question explicitly adopts it, but it is not adopted in the actual history. The rental has no output of its own and does not add a fourth job. A planner examining this option must recheck every limiting resource. Satisfying a previously tight staff inequality does not erase independent memory or power requirements.

## D09 — Day 9, alternative requirement

A stakeholder says that a future demonstration might require job A to be included. This request is not adopted for the current session; the present objective is still maximum output from any feasible pair. The coordinator asks the handoff to retain what would need to change if A later became mandatory. The project has no universal rule that the currently best pair remains best under a new inclusion requirement. The alternative must be evaluated from the original job requirements and whatever caps the new question actually supplies.

## D10 — Day 10, separate memory option

A separate option could add one memory unit, taking the adopted nine-unit cap back to ten. This option would leave staff and power at eight unless another change were separately specified. The option is not adopted before the cutoff. It must not be merged with the staff rental merely because both appear in the planning discussion. The two options affect different constraints and can be considered independently. The current plan includes neither option, and no resource measurement or job requirement is revised on this date.

## D11 — Day 11, reporting request

The incoming planner should state the selected pair, its total output, and its combined use of each resource. If asked about a rejected alternative, the explanation should identify the actual binding violations, not merely say it lost to another pair. If the objective changes, the planner should distinguish the original optimum from feasibility under the changed requirement. The finite catalogue is small enough that no search budget issue arises. A calculation that covers all three pairs is complete for this scenario, without claiming anything about larger scheduling problems.

## D12 — Day 12, cutoff

The final adopted caps are eight staff units, nine memory units, and eight power units. Job A still has requirements (4,6,4) and output 8; B has (5,5,5) and output 10; C has (3,4,3) and output 6, in staff, memory, power order. Exactly two distinct jobs must run simultaneously. No rental or extra memory has been adopted. The future A-inclusion request remains hypothetical. This final inventory is a convenient restatement of the primitives, not a replacement for the chronology explaining which earlier proposals and budgets are no longer current.
